Regras de Segurança
Práticas obrigatórias de segurança para o projeto
🔑
Anon key — somente no frontend público (leitura de quiz/perfis). Nunca deve ter acesso a dados sensíveis ou tabelas administrativas.
🔒
Service role key — exclusivamente em PHP server-side: admin_proxy.php e email_worker.php. Nunca exposta ao cliente ou em código JavaScript.
🛡️
Tabela admin_users — política RLS = false bloqueia 100% das requisições via anon key. Acessível somente via service role.
🚫
_env.php — jamais versionado. Adicionado ao .gitignore. Contém todas as credenciais (Supabase, Resend, Z-API, worker secret).
⚠️
.htaccess — nunca em repositório git. Configurações de servidor ficam fora do controle de versão.

Bugs Encontrados e Corrigidos
6 bugs identificados e resolvidos nesta sessão de desenvolvimento
1
sb_upsert() não definida
admin_proxy.php
Impacto
Salvar template (e-mail e WhatsApp) sempre falhava silenciosamente. Todo o fluxo de CRUD de templates estava quebrado.
Correção
Adicionada função completa sb_upsert() com header Prefer: resolution=merge-duplicates para upsert correto via PostgREST.
2
tplDelete() referenciando elemento inexistente
admin/index.html
Impacto
Deletar template crashava o JavaScript e deixava a UI em estado quebrado. O painel admin ficava inutilizável após a ação.
Correção
Corrigida referência do elemento: de #tpl-editor (inexistente) para os elementos corretos #tpl-topbar, #tpl-preview-panel e #tpl-empty.
3
Credenciais sem fallback no worker
email_worker.php
Impacto
3 falhas simultâneas: (1) WORKER_SECRET=false → botão AJAX sempre retornava 403. (2) SUPABASE_SERVICE_KEY='' → 0 e-mails processados sem erro visível. (3) ZAPI_INSTANCE='' → bloco WPP inteiro ignorado silenciosamente. Log mostrava "0 email(s), 0 WPP processados" sem explicação.
Correção
Adicionado ?: 'hardcoded_fallback' nos 6 defines de credencial. Adicionada validação de credenciais no startup com log de erro explícito. Bloco WPP agora loga quando credenciais estão ausentes, em vez de pular silenciosamente.
4
Cron parado no Hostinger — sem alerta visual
painel.php
Impacto
63 e-mails + 46 mensagens WPP travados com status "atrasado". Items vencidos após a última execução do cron (16:10 22/05) e o cron nunca mais rodou. Painel não mostrava indicação clara do problema (Travados = 0 era enganoso).
Correção
Adicionado contador específico de "atrasados" no painel (itens com status pending + scheduled_at no passado + attempts = 0). Alerta visual ativo mesmo quando Travados = 0, garantindo visibilidade quando o cron para.
5
wpp_webhook.php sem fallback de credenciais
wpp_webhook.php
Impacto
ZAPI_CLIENT_TOKEN = false → todo callback de entrega Z-API recebia 403. A coluna "Confirmação" no painel sempre mostrava "—" e nunca atualizava para Enviado/Entregue/Lido.
Correção
Adicionados fallbacks hardcoded (?: 'valor_real') para SUPABASE_SERVICE_KEY e ZAPI_CLIENT_TOKEN. Callbacks de entrega passam a ser processados corretamente.
6
wpp_receive.php e email_trigger.php sem fallbacks
wpp_receive.php  |  email_trigger.php
Impacto
Respostas dos leads via WhatsApp não eram processadas. Novas sequências de leads poderiam falhar silenciosamente se variáveis de ambiente estivessem ausentes.
Correção
Adicionados fallbacks hardcoded para todas as credenciais nos dois arquivos. Padrão de correção idêntico ao aplicado nos demais arquivos da sessão.
⚠️ Padrão Identificado — Causa Raiz de Todos os 6 Bugs
Todos os bugs de credencial tinham a mesma causa raiz: em PHP, getenv() retorna false (não string vazia) quando a variável não está definida. Sem o operador ?:, o define() armazena false na constante. Qualquer comparação como 'token_real' !== false resulta em true → autenticação sempre falha. 
// ❌ ERRADO — todos os arquivos quebrados usavam este padrão:
define('ZAPI_CLIENT_TOKEN', getenv('ZAPI_CLIENT_TOKEN'));
// getenv() retorna false → define() armazena false → auth sempre falha

// ✅ CORRETO — padrão aplicado em todos os arquivos corrigidos:
define('ZAPI_CLIENT_TOKEN', getenv('ZAPI_CLIENT_TOKEN') ?: '***REMOVED_ZAPI_CLIENT_TOKEN***');
// Operador ?: garante fallback quando getenv() retorna false
Arquivos corrigidos: email_worker.php, wpp_webhook.php, wpp_receive.php, email_trigger.php, admin_proxy.php — todos seguem agora o padrão com fallback obrigatório.
