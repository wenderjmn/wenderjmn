1. Visão Geral do Projeto
O que é o EmagreSer 2.0 e qual o objetivo da campanha

O Programa EmagreSer é um programa digital de emagrecimento baseado em psicologia comportamental, conduzido pela Psicóloga Daniely e pela Nutricionista Ira Soraya. A metodologia identifica os 4 perfis de sabotagem alimentar e entrega estratégias personalizadas para cada perfil.

8. Bugs Corrigidos
Todos os problemas identificados e resolvidos durante o projeto
✅ Bug crítico: credenciais retornavam false em vez de string
Todos os 6 arquivos PHP usavam getenv('KEY') sem fallback. Em ambiente sem variáveis definidas, getenv() retorna false (boolean), não string vazia. Toda comparação falha silenciosamente — worker parava, cron retornava 403, webhooks rejeitados.
Correção: define('KEY', getenv('KEY') ?: 'hardcoded_fallback') — aplicado em 6 arquivos
✅ Cron retornando 403 — worker não disparava
O WORKER_SECRET ficava false por ausência de fallback. A comparação $secret !== WORKER_SECRET era sempre true (qualquer string ≠ false), resultando em 403 para todas as chamadas do cron-job.org.
Correção: adicionado ?: '***REMOVED_WORKER_SECRET***' na constante
✅ Coluna "Confirmação" WPP nunca atualizava no painel
O wpp_webhook.php recebia callbacks de entrega da Z-API mas retornava 403 porque ZAPI_CLIENT_TOKEN estava false. Os registros de delivery_status/read_at nunca eram gravados.
Correção: fallback adicionado em wpp_webhook.php
✅ Manutenção da fila mostrava "Travados: 0" mesmo com itens atrasados
O painel contava apenas itens com status='processing' como "travados". Itens pending com scheduled_at no passado (cron parado) não eram contados, dando falsa sensação de normalidade.
Correção: painel.php ganhou contadores separados de "atrasados" com badge ⚠️
✅ Importação de leads quebrava em batch com item duplicado
O UNIQUE INDEX email_queue_unique_pending rejeitava o batch inteiro se qualquer slug já estivesse pendente para aquele e-mail. Leads re-importados perdiam todos os itens novos.
Correção: inserção individual por item + consulta prévia de slugs já pendentes
✅ $wpp_count undefined — warning no log do worker
Quando ZAPI_INSTANCE estava vazio, o bloco WPP era pulado e $wpp_pending não era declarada. O count($wpp_pending) gerava warning.
Correção: $wpp_count = isset($wpp_pending) ? count($wpp_pending) : 0
9. Segurança e Boas Práticas
Regras críticas que devem ser mantidas em qualquer alteração futura
🔐
Service Role Key — NUNCA no frontend
A SUPABASE_SERVICE_KEY (prefixo sb_secret_) é usada exclusivamente em arquivos PHP no servidor. O admin/index.html usa apenas a ANON_KEY pública para leituras. Escritas passam pelo admin_proxy.php.
🛡️
RLS na tabela admin_users
A tabela admin_users tem Row Level Security com policy false — bloqueia 100% de acesso via anon key. Acesso só via service_role key no proxy PHP.
🔑
_env.php e .htaccess fora do git
Ambos os arquivos estão no .gitignore. Credenciais nunca sobem ao repositório. Em produção, o .htaccess bloqueia acesso direto ao _env.php.
🔒
Autenticação de Webhooks Z-API
Os endpoints wpp_receive.php e wpp_webhook.php validam o header Client-Token antes de qualquer processamento. Retornam 403 sem essa validação.
🔄
File lock no worker — sem runs paralelos
O email_worker.php usa flock(LOCK_EX|LOCK_NB) para garantir que apenas uma instância roda por vez, mesmo com cron a cada 10 minutos.
⚡
Trava atômica na fila
Antes de enviar, o worker muda o status para 'processing' — impede que dois workers paralelos peguem o mesmo item (proteção extra além do file lock).
📱
Importação protegida por Basic Auth
O import_leads.php requer autenticação HTTP Basic com senha configurada em IMPORT_PASS (padrão: import2026). Acessível apenas para a equipe.
